# 110_给静静的梦灯笼实机失败返工_双镜门与伪动态渲染器_v1.0

日期：2026-10-20
项目：《狐妖小红娘·梦灯笼》
状态：v1.3.0 实机视觉验收失败；本单为强制返工，不是新设计。

## 0. 失败结论

用户 Android/SillyTavern 实机截图已经证明：

1. 前尘/今世并未表现为“两面镜子”，只是两块暗色矩形卡。
2. 篇章详情/Opening 仍主要表现为单张静态海报。
3. 用户未观察到红线、狐火、花瓣、沙尘、雾、雪、镜光、剑光等冻结 FX 演出。
4. “官方静态·梦灯轻动”文字存在，但可见动效不足，不能作为完成证明。
5. 多图拼接/叠化伪动态没有形成用户可感知的演出。

因此：v1.3.0 不得视为 109 视觉装配完成。

## 1. 根因

当前仓库虽然已有：
- manifest/dynamic-runtime.v1.json
- manifest/fx-profiles.v1.json
- ui/dreamlantern.runtime109.css

但仅有 manifest + CSS 不足以构成运行时演出。CSS 依赖真实 DOM 节点，例如：
- .dl-thread
- .dl-fox-glow
- .dl-petal
- .dl-mote
- .dl-109-extra / .dl-110-extra

如果 JS 没有按 fxProfile 创建这些节点，特效就不会出现。

另外，chapter images manifest 中部分卷只有 primary 单图，secondary 为空。多图卷与单图卷必须分别处理：
- 多图卷：真正做 montage 叠化/切镜。
- 单图卷：做明显但克制的 Ken Burns 镜头 + FX，禁止仅静止。

## 2. 已补好的实现件

绒绒已经直接在仓库 main 新增：

- ui/dreamlantern.runtime110.js
- ui/dreamlantern.runtime110.css

静静不得重写艺术方向，直接接入这两个实现件并适配现有正式卡 DOM。

runtime110.js 提供：

```js
DreamLanternRuntime110.mountMirrors(root)
DreamLanternRuntime110.mountOpening(root, chapterId, options)
DreamLanternRuntime110.dispose(root)
```

### 2.1 mountMirrors(root)

必须用于缘卷首页时代选择区。
效果必须是：
- 前尘、今世两块视觉上明确的立式古镜/梦镜；
- 金属/灯金镜框；
- 深色镜面；
- 镜面反光；
- 两镜之间有一根红线；
- 仍保持原有时代选择业务逻辑不变。

禁止继续使用“两块普通矩形按钮”的表现。

### 2.2 mountOpening(root, chapterId)

必须在每次篇章 Opening/重温页面挂载后调用。
它会：
- 读取 dynamic-runtime.v1.json；
- 读取 fx-profiles.v1.json；
- 读取对应卷 images/manifest.json；
- 创建真实 montage 图层；
- 创建红线/狐火/花瓣/粒子/extra 特效 DOM；
- 设置 data-dl-fx-mounted 与 data-dl-fx-profile 作为实机验收钩子。

没有调用这个函数，就不能宣称 110 完成。

## 3. 多图拼接伪动态硬要求

### 3.1 有多张正式图的卷

必须：
- primary + secondary 去重；
- 最多取 4 张；
- 同一个 Opening 内真实叠化/切镜；
- 每张图使用不同轻微缩放/位移；
- 不允许只创建第二张 img 但 opacity 永远为 0；
- 不允许页面加载后只停留在第一张。

### 3.2 只有一张正式图的卷

不能假装“多图”。
必须：
- 单图镜头慢推/轻平移；
- FX按本卷 profile 实际运行；
- 标题/副标题有渐入；
- 让用户明确感知这是 Opening，而不是海报详情页。

### 3.3 后续资源补充

如后续给某卷增加 secondary/memory 可用于 Opening 的正式图片：
- 只更新对应 images/manifest.json；
- runtime110 自动获得更多 montage shot；
- 不改 MVU。

## 4. 前尘/今世“双镜门”硬验收

用户明确要求的是“两面镜子”。

Android 实机必须肉眼可见：
- 前尘：一面古旧暖金镜；
- 今世：一面暗红/墨紫梦镜；
- 两者不是普通卡片；
- 镜框轮廓明显；
- 镜面有微弱扫光；
- 中间红线缓慢牵连；
- 点击区域仍完整，触控不受特效层阻挡。

如果截图看起来仍然只是两块矩形斑块：FAIL。

## 5. 实机可见特效硬验收

至少抽验以下 6 卷：

- M01 下沙：镜头运动 + 沙尘/暖粒子 + 红线；
- M03 王权：镜头运动 + 金色剑光 + 红线；
- M04 月红：镜头运动 + 双红线 + 花瓣 + 暖背光；
- M06 南国：镜头运动 + 紫雾 + 狐火；
- M09 镜花缘：品牌景 + 镜面折光 + 双红线；
- M13 新北山：品牌景 + 慢雪 + 冷雾。

每一卷都必须提供 Android/SillyTavern 实机截图；另外 M03/M04/M06/M13 至少各提供 2 张相隔 2~4 秒的截图，证明画面状态有变化。

不接受：
- 浏览器静态DOM检查代替实机；
- CSS文件存在代替视觉证据；
- QA JSON 写 PASS 但没有实机图；
- 标签写“轻动”但实际肉眼看不出；
- 仅“查看官方动态”按钮作为动态完成证据。

## 6. reduced-motion

必须尊重 prefers-reduced-motion，但 QA 时需要明确记录设备状态。

若用户设备没有主动开启“减少动态”：
- 正常模式必须出现 Dream FX。

若 WebView 误判 reduced-motion：
- 记录环境与判断结果；
- 不得用“系统可能减少动态”掩盖渲染器未挂载的问题。

runtime110 提供 data-dl-fx-mounted：
- "1" = FX 已挂载；
- "reduced" = 因 reduced-motion 有意关闭；
- "error" = 挂载失败。

Android QA 必须记录这三个状态之一。
