# 119_给静静的118候选5实机返工_选卷后恢复入口视频生命周期_v1.0

日期：2026-10-21  
项目：《狐妖小红娘·梦灯笼》  
唯一直接基线：`118候选5`，当前交付 HEAD `cebe1a1727c9a11be9e396a41f9a63d1c591165e`。  
目标：修复两项实机/结构问题：①选择并进入任意缘卷后，返回总入口时 `rukou.mp4` 不再显示；②角色世界书条目存在“只用超长全称才能触发”的关键词问题，按咩咩制卡包·全栈标准做全量 alias 正则审计。

## 一、现象

118候选5首次加载总入口时，`rukou.mp4` 已恢复可见；时代页、双阶段点击、有声时代预览也正常。

但用户完成：

`展开狐妖手札 -> 前尘/今世 -> 选择卷 -> 由此入梦/进入卷 -> 返回聊天主界面总入口`

之后，总入口只剩当前卷的静态官方图/scene，`rukou.mp4` 不再显示。

这不是媒体文件或映射错误，而是**入口播放器生命周期在“选择卷后返回总入口”这一状态迁移中没有重新挂载**。

另外，实机检查发现部分角色世界书条目的 regex 只保留过长正式称谓，例如类似：

`/<story_scene>.*?(极北萨摩王故义).*?<\/story_scene>/s`

这会导致正文必须完整写出“极北萨摩王故义”才触发角色条目，不符合咩咩全栈角色 alias 触发规范。

## 二、根因约束

117/118 已明确要求：

- 打开手札/时代页时入口播放器必须停止、静音、卸载并 detach，避免串台；
- `mountIntro()` 在 shade/手札可见时不得挂载入口视频；
- 118 只修了初始入口的层级与可见性。

因此选卷流程中，入口在进入手札时被正确清理；但当手札关闭、回到聊天主界面时，如果只恢复 `.dl-intro` DOM/静态 scene，而没有在 **shade 真正 hidden 且旧媒体 clear 完成以后**重新调用入口媒体挂载，就会出现本次回归。

不得通过取消117的隔离清理来“修复”。正确修法是补齐**返回入口后的 remount 生命周期**。

角色关键词问题则来自 alias group 不完整：条目虽然 `use_regex=true`，但括号中只有一个冷门/超长正式全称，实际等同于没有做简称/昵称/称号召回。

## 三、必须修成的行为

### 3.1 总入口视频恒定语义

只要当前处于聊天主界面的总入口、手札 overlay/shade 已关闭，入口主视觉必须优先为：

`incoming/mp4_raw/rukou.mp4`

无论：

- 尚未选择任何缘卷；
- 已选择古代任意卷；
- 已选择现代任意卷；
- 已多次进入/退出手札；
- 已重温 Opening 或回看时代入口；

`rukou.mp4` 都必须重新出现并正常播放。

当前卷官方图只允许作为：

- 视频加载中的 fallback/poster；
- 视频失败时的 fallback；
- 其他非入口展示层背景。

**不得因为 `_当前篇章` 已存在，就用该卷官方图永久替换总入口 `rukou.mp4`。**

### 3.2 生命周期顺序

关闭手札/overlay 回到总入口时，必须遵守：

1. `shade.hidden = true`（或等价：先确认 overlay 已不可见）；
2. 完成 `stopVisual()/mediaLayer.clear()` 对 overlay/时代/Opening 媒体的清理；
3. 恢复 `.dl-intro` 的可见/非 muted-scene 状态；
4. 找到当前实际存在且可见的 `.dl-intro` host；
5. 再调用 `enhanceIntro(host)` / `mediaLayer.mountIntro(host, ...)` 重新挂载 `rukou.mp4`；
6. 若 DOM 在本轮刚重建，可使用 microtask / `requestAnimationFrame` / 明确的 post-render hook，但必须保证只挂载一次。

禁止在 shade 仍可见时提前 mount，然后被 `mountIntro()` guard 拒绝后就不再重试。

### 3.3 选卷进入后的处理

`enter(id)` / 卷选择事务完成后：

- 业务状态、世界书、当前篇章写入逻辑保持118原样；
- 不得在 overlay 尚未关闭时把 `rukou` 强塞回来；
- 当流程真正返回聊天主界面入口后，必须触发一次统一的 `restoreIntroAfterOverlay()`（名称可不同）生命周期；
- 入口视频 URL 始终来自 `manifest.intro.video`，不得改成当前卷 Opening/官方图 URL。

### 3.4 保留现有正确行为

本轮禁止破坏：

- 时代页只有前尘/今世两张卡；
- `rukou` 不得出现在时代页；
- 第一次点时代卡=有声预览；第二次点同卡=进入时代；
- 切卡时正确释放旧时代播放器；
- Opening 点击卷后直接播放；
- 默认特效开启；
- 21卷映射；
- 世界书/MVU业务规则；
- 117的入口/时代独立 media channel；
- 118的入口视频层级、像素可见性与声音按钮逻辑。

## 四、实现建议

优先做一个单一生命周期入口，例如：

`restoreIntroAfterOverlay()`

职责仅为：

- 确认 `shade.hidden === true`；
- 确认 `.dl-intro` 存在且当前页面是总入口；
- 清除 stale intro 状态/旧实例引用（如有）；
- 调用现有 `enhanceIntro()` 或 `mediaLayer.mountIntro()`；
- 防止重复 video / 重复声音按钮。

建议 `close()` 最终顺序类似：

`hide shade -> stop overlay media -> restore intro DOM state -> restoreIntroAfterOverlay()`

而不是：

`mount intro -> stopVisual()`

后者会立刻把刚挂载的入口视频再次 clear 掉。

## 六、角色世界书关键词：严格按咩咩制卡包·全栈规范

### 6.1 固定 regex 外壳

所有“角色出现时召回”的角色世界书条目统一使用：

```regex
/<story_scene>.*?(关键词1|关键词2|关键词3).*?<\/story_scene>/s
```

JSON 中 `keys` 只保留该角色对应的这一条 regex 字符串；保持：

- `constant: false`
- `selective: true`
- `use_regex: true`
- `position: after_char`
- `probability: 100`
- 现有 depth 若已按咩咩全栈配置则保持不变

禁止把多个普通关键词数组与 regex 混用作为主触发方式。

### 6.2 alias group 必须全量审计

不是只修“极北萨摩王故义”一个条目。必须扫描候选6内**全部角色世界书条目**，为每位角色建立 alias group，至少检查：

- 正式全称；
- 正文最常用名字；
- 确认存在的简称；
- 确认存在的昵称/别称；
- 明确且不会误触的头衔；
- 剧情中确实会自然出现的旧名/原名；
- 必要且有资料依据的译名变体。

不得凭空创造昵称或别称。

### 6.3 本轮示例

当前问题条目类似：

```regex
/<story_scene>.*?(极北萨摩王故义).*?<\/story_scene>/s
```

必须根据该角色在现有资料/角色正文中的实际称呼审计后改为 alias group。若现有正式资料确认这些称呼均成立，则应类似：

```regex
/<story_scene>.*?(极北萨摩王故义|故义|极北萨摩王|萨摩王).*?<\/story_scene>/s
```

其中 `故义 / 极北萨摩王 / 萨摩王` 只有在现有角色档案、时间线或正文确实如此称呼时才保留；不得仅因为字符串可拆分就机械加入。

### 6.4 禁止过宽误触

alias 要“自然可触发”，但不能为了短而短。

禁止加入会大量误触的普通词，例如单独：

- 王
- 妖
- 狐
- 姐姐
- 长老
- 家主
- 道士

除非某个词在项目资料中确实是该角色唯一稳定专名且不会与其他角色冲突，否则不得作为独立 alias。

### 6.5 同角色关联条目复用同一 alias group

若同一角色除人物卡正文外还有：

- 同名能力条目；
- 核心设定条目；
- 角色专属知识/补充条目；

且这些条目本来就是依赖“该角色当前在 `<story_scene>` 中出现”触发，则复用同一份角色 alias regex，不得人物条目用简称、能力条目却仍只认超长全称。

不要改变这些条目原有 enabled/disabled、权限、正文内容和业务语义；本轮只修触发 keys/selective 结构。
